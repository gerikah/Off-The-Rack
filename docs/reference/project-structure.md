# Project structure

```text
assets/                     Original photography, logos, and email design source
docs/
  archive/                  Historical reports and measurements
  reference/                Architecture, folder structure, and operational notes
  setup/                    Admin and email configuration guides
public/                     Public URLs: optimized images, icons, and social artwork
scripts/                    Build, asset, test, and audit tools
src/
  app/                      Next.js routes, layouts, server actions, and API handlers
  components/
    admin/                  Internal workspace components
    catalog/                Product cards, gallery, actions, and shop filters
    forms/                  Inquiry, newsletter, and unsubscribe forms
    layout/                 Navigation, footer, and route-specific page chrome
    shared/                 Shared controls, loading placeholders, and structured data
  lib/
    admin/                  Admin authorization, validation, data, and image operations
    catalog/                Product image helpers, copy limits, and browser saved pieces
    data/                   Server catalog queries and public form persistence
    email/                  Loops integration and email types
    images/                 Image validation and processing
    newsletter/             Legacy campaign content, delivery, and unsubscribe tokens
    security/               Public form validation and per-instance request protection
    supabase/               Public client, cookie-aware server client, and session refresh
  styles/                   Storefront and admin stylesheets
  proxy.ts                  Next.js request proxy entrypoint
supabase/                   Database migrations, development seed, and verification SQL
  functions/subscribe/      Existing standalone subscription function and its configuration
tests/                      Browser, validation, and isolated backend fixtures
.work/                      Ignored local output, screenshots, reports, and TypeScript cache
```

Next.js configuration, package manifests, environment files, agent instructions, and the primary README stay at the project root so the framework and development tools can discover them.

The `supabase` migration order and public asset URLs are preserved. Original image files in `assets` remain inputs to `npm run assets`; files in `public` may also be referenced by database records and development seeds.

## Generated output

- Next.js owns `.next/`; it is generated by development and production builds.
- Browser results and the HTML report are written to `.work/test-results/` and `.work/playwright-report/`.
- TypeScript's incremental cache is written to `.work/tsconfig.tsbuildinfo`.
- Historical bundle measurements stay under `docs/archive`; run `npm run analyze:bundle` after a production build for fresh measurements.

## Cleanup decisions

The unused `EditorialImage` component, obsolete available/bestseller/related catalog queries, and unused `SubscriptionStatus` type were removed after checking source and test imports. Helpers used only within their own module are private.

The unreferenced Upstash rate-limit module and its two dependencies were removed. Active public form validation and database quotas continue through `src/lib/security/public-request.ts` and the existing SQL migrations. See [rate limits](rate-limiting.md) for the implemented behavior.
